# P4 — экспериментальный интерактивный граф v2 в SPA

**Статус:** draft / PR-only preview, 11 октября 2026. Основной сайт **не изменён**. P4 не является переоценкой исторических фактов и не устанавливает истинность источников. [RFC](SCHEMA_V2_RFC.md), [P1 идентификаторы](SCHEMA_V2_CROSSWALK.md), [P2 должности](SCHEMA_V2_ROLES.md), [P3 граф отношений](SCHEMA_V2_RELATIONS.md).

## Пользовательский сценарий

На **отдельной экспериментальной сборке существующего SPA** появляется ссылка «Сеть династий v2 · открыть». Граф также открывается по URL-параметру:

`?atlasV2=graph&v2Year=1788#/timeline/1762`

Обновление обычной шкалы и её вкладок не требуется. Закрытие нового режима возвращает к прежнему экрану, Browser Back/Forward сохраняются.

Внутри доступны:
- Год 1762–1800: ползунок, кнопки назад/вперёд, восстановление года из URL (`v2Year`).
- Шесть независимых переключателей: **династические дома**, **родство и брак**, **преемственность/регентство**, **личные унии**, **договоры**, **учреждения и режимы**. Текущее сочетание хранится в `v2Links`.
- **Граф SVG:** дома, документированные участники, коллективные учреждения и исторические политические контексты — разные типы узлов. Правящие юридические сроки — сплошные связи, консортство/генеалогия — пунктирные. Цвет не обозначает «национальность».
- Нажатие/Enter/Space на узел или документированное отношение раскрывает пояснение, роль и ссылки на **HTTPS-источники** с `target=_blank` и `rel=noopener noreferrer`.
- Отдельный доступный список отношений; на телефоне длинный SVG прокручивается внутри собственной области, а контролы имеют целевой размер не менее 44 px.

Состояние не объединяет Французскую монархию с Французской республикой, Великобританию с Ганновером или владения Габсбургов с выборной должностью императора СРИ. У графа **нет** геометрии исторических границ.

## Архитектура и происхождение данных

`data/atlas/**` (неизменяемый канон Git) и `data/atlas/world-pilots/**` → проверенная временная SQLite v1 → P1 crosswalk → P2 роли → P3 типизированные отношения → **[scripts/atlas_v2_graph_preview.py](../scripts/atlas_v2_graph_preview.py)** → `atlas-v2-graph.json` → [JS](../site/atlas-v2-graph.js) + [CSS](../site/atlas-v2-graph.css).

Экспорт строится **SQL-запросами поверх P3**, а не конструируется из имён/цветов/современной карты на фронтенде. Никакого AI или внешних SDK в браузере.

P4 намеренно ограничен международной исследовательской выборкой 1762–1800:
- 13 исторических международных контекстов (включая несамостоятельные юридические);
- 28 отдельных world-ID людей, из них 4 сопоставлены российскому канону и 24 оставлены неразрешёнными;
- 4 документированных дома, 18 атрибутированных связей с домами;
- 43 роли/учреждения, 27 нормализованных отношений, с ссылками на существующие источники.

Источники каждой роли, родственной связи и дома переносятся через `v2_assertion_sources`. Исходные 29 записей двух повторяющихся событий и остальные материалы остаются в своих источниковых наборах, без дублирования нормализованного графа. Экспорт сохраняет `start_year/end_year` и caveat, а там, где дата обрезана рамкой выборки, не выдаёт её за начало/конец фактической должности.

Для `documented_house` сама принадлежность **не имеет полной проверенной датировки**; поэтому ребро дома показывается только при наличии документированной роли человека в выбранном году. Граф не утверждает, что источниковое окно брака означает его полный срок, а год рождения родителя равен времени, к которому относится свидетельство. При выборе года мы показываем **кандидатов пересечения источниковых окон** — не доказанную одновременность полномочий в день.

## Как запустить локально

**Этап 1.** В PR-ветке выполнить обычную проверенную сборку `dist`:

```sh
python3 scripts/soviet_audit.py --revision "$(git rev-parse HEAD)"
python3 -m scripts.extend_century
python3 -m scripts.extend_romanovs
python3 -m scripts.extend_muscovy
python3 -m scripts.atlas_db build
python3 -m scripts.smuta_map --revision "$(git rev-parse HEAD)"
```

**Этап 2.** Создать из `dist` самостоятельный preview без изменения исходной директории:

```sh
python3 -m scripts.atlas_v2_graph_preview --dist dist --output p4-preview
python3 -m http.server 8765 --directory p4-preview
```

Открыть [http://127.0.0.1:8765/?atlasV2=graph&v2Year=1788#/timeline/1762](http://127.0.0.1:8765/?atlasV2=graph&v2Year=1788#/timeline/1762). `fetch` требует HTTP-сервер; простое открытие локального `file://index.html` не является поддерживаемым вариантом.

**Другой путь без локальной сборки:** открыть GitHub Actions в PR #38, выбрать успешный запуск **Historical atlas audit**, скачать артефакт **`historical-atlas-v2-graph-preview`**, распаковать ZIP, запустить `python3 -m http.server 8765` внутри распакованной папки и открыть ссылку выше.

## CI и релизные ограничения

Только для события `pull_request` тестовый workflow дополнительно:
1. Создаёт `p4-preview/` после проверенной оригинальной сборки `dist`.
2. Запускает [браузерные проверки](../tests/browser_schema_v2_graph.py) в Chromium на 1440×960, 390×844, 320×640 и 844×390: граф/фильтры, личная уния 1762, французские учреждения 1795, открытие источников, мобильная прокрутка, keyboard, URL/history и возврат в прежний SPA.
3. Сохраняет ZIP-артефакт `historical-atlas-v2-graph-preview` с ограниченным сроком хранения (14 дней); тестовые изображения/receipts — в прежнем browser-evidence.

**Не изменены** `schemas/atlas.sql`, `scripts/atlas_db.py`, канонические люди/должности, оригинальное фото, production `dist`, основной билд и [строгий allowlist GitHub Pages](../.github/workflows/publish-pages.yml). Превью НЕ разворачивается на главном адресе и не становится видимым при обычном посещении сайта.

## Что потребуется перед возможной публикацией

- Приёмка мобильного и настольного SVG-графа на физических устройствах.
- Историческая экспертиза спорных дат/династических классификаций; поиск дополнительных источников для неполного покрытия.
- Отдельная политика перехода от 1762–1800 к другим векам, чтобы не смешивать «источника нет» и «правитель отсутствует».
- Отдельный выпуск канонического контракта экспорта, feature flag/публикационного allowlist, и решение о слиянии draft PR. Никакой автоматической production-миграции здесь нет.
