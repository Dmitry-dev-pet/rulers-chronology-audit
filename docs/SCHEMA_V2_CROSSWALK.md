# Crosswalk v2: связь русского канона с европейским пилотом

**Статус:** proposal, не продукционная миграция. Пилотная сверка сделана 11 октября 2026 года на исторических записях репозитория; это не независимая историческая экспертиза. [Основной RFC](SCHEMA_V2_RFC.md).

## Для чего нужна таблица соответствий

В каноне v1 есть **6** исторических контекстов (`states.jsonl`). В европейских пилотах — **13** контекстов (`1762.json` + `dynasty-1762-1780.json` + `extension-1781-1800.json`). Это не 19 разных государств: международный `ru` уже явно указывает `canonical_state_id="empire"`. Следовательно, **18** уникальных типизированных контекстов и **19** ссылок на исходные ID.

Остальные международные политии не связываем автоматически с российскими контекстами; имена, современная страна, происхождение правителя или общая династия **не** доказывают идентичность государств.

В трёх наборах людей: **28** уникальных world-ID, из которых **ровно 4** уже связаны с российским каноном по `canonical_person_id` и `canonical_tenure_id`: Пётр III, Екатерина II, Елизавета Петровна, Павел I. **24** внешних world-персоны остаются `unresolved`, даже если имя известно. Так предотвращаем случайное объединение двух исторических лиц только по фамилии/имени.

Источники тоже имеют отдельное пространство имён: **194** канонических записей и **43** из пяти международных партий, итого **237** зарегистрированных ссылок. Совпадение заголовка или домена источника не означает, что две источниковые записи можно слить.

## Реестр и точные связи

Редактируемый **черновик** — [`design/atlas-v2/crosswalk-proposal.json`](../design/atlas-v2/crosswalk-proposal.json). Прямая таблица:

| Источник | Исходный ID | Куда попадает | Семантика |
|---|---|---|---|
| Канон v1 | `empire` | `ctx-empire` | Российская империя (исторический контекст) |
| World 1762–1800 | `ru` | `ctx-empire` | Единственное прямое совпадение, задано `canonical_state_id` |
| Канон v1 | `tsardom` | `ctx-tsardom` | Русское царство, **не** склейка с империей |
| Канон v1 | `moscow` | `ctx-moscow` | Московское великое княжество, самостоятельный контекст |
| Канон v1 | `russia-1917` | `ctx-russia-1917` | Временное правительство, не тождественно СССР |
| Канон v1 | `rsfsr` / `ussr` | `ctx-rsfsr` / `ctx-ussr` | Два контекста, не одна территория |
| World 1762–1800 | `fr` / `frrep` | `ctx-world-fr` / `ctx-world-frrep` | Монархия и республика Франции — разные режимы |
| World 1762–1800 | `gb` / `han` | `ctx-world-gb` / `ctx-world-han` | Один Георг III, но два политико-правовых образования |
| World 1762–1800 | `hab` / `hre` | `ctx-world-hab` / `ctx-world-hre` | Составная монархия / выборная императорская должность |
| World 1762–1800 | `meck` | `ctx-world-meck` | Изучено как **место рождения**, не как список монархов |
| World 1762–1800 | `pr`, `es`, `pt`, `sw`, `tusc` | `ctx-world-…` | Отдельные контексты; новых совпадений не домысливаем |

**Важно:** `ctx-empire` / `ctx-tsardom` — разные сущности при возможной исторической преемственности. Сама преемственность требует отдельного датированного источникового отношения, а не слияния ID. Аналогично личная уния Великобритании и Ганновера — отношение между двумя контекстами, а не тождество государств.

Полития, режим, составные владения, выборная императорская должность и контекст места рождения имеют разные `kind`; итоговые графики не должны суммировать их как равноправные суверенные государства.

## Откуда берутся соответствия и как их проверяем

- Политии: **только** из поля `canonical_state_id` у исходного пилота. Сейчас оно указано для `ru → empire`; отсутствие этого поля значит **нет автоматического соответствия**, а не «страну не удалось найти».
- Лица: **только** из существующих `canonical_person_id` и `canonical_tenure_id` в международном пилоте. Проверяются FK, совпадение `tenure.person_id` и полнота всех 28 world-ID.
- Должностные ссылки `roles[].canonical_tenure_id` сверяются с записанным person-crosswalk.
- Династии не используются для слияния людей или государств. Международный `houses` и `dynasty-footprints` остаются самостоятельными источниковыми слоями до P2.
- Источники: `(origin, native_id)` — ключ источника. Если в будущем голый source-ID начнёт означать две разные записи, сборка должна остановиться до явного исправления (сейчас нет таких коллизий).
- Типы `hre/hab/meck` жёстко проверяются, как и пять пар контекстов, которые нельзя сливать.
- Матрица покрытия используется для проверки наличия 13 world-контекстов, но не превращает пробелы в «отсутствие государя».
- Никаких новых утверждений о границах, этнической принадлежности или непрерывном политическом контроле.

## Пробная сборка и откат

`scripts/atlas_v2_crosswalk.py` — валидатор + сборщик **одноразовой копии SQLite**. Он читает канонические файлы и международные пилоты, строит v1 SQLite во временном каталоге, копирует в память, применяет `schemas/atlas_v2_candidate.sql` и заносит только сопоставления `v2_contexts`, `v2_context_refs`, `v2_external_people`, `v2_sources`.

Команда из корня репозитория:

```bash
python3 -m scripts.atlas_v2_crosswalk
python3 -m unittest discover -s tests -p 'test_schema_v2_crosswalk.py' -v
python3 -m scripts.atlas_db validate
```

В CLI-выводе должны быть: **18** контекстов, **19** ссылок на контексты, **28** внешних персон (**4 linked**, **24 unresolved**), **237** источников и `PRAGMA integrity_check = ok`, `user_version=1`.

**Не изменяются:** `data/atlas`, `schemas/atlas.sql`, `scripts/atlas_db.py`, `dist`, текущие даты/источники, оригинальное фото в закрытом Drive и живой сайт GitHub Pages. Откат P1 означает просто отказаться от чернового PR: он не делает постоянных изменений в SQLite или SPA.

## P2 реализован как экспериментальная проекция

Новый этап описан в [SCHEMA_V2_ROLES.md](SCHEMA_V2_ROLES.md). Модуль `scripts/atlas_v2_roles.py` загружает 40 персональных world-ролей и 3 учреждения Французской республики в **одноразовую** SQLite-память, сохраняя исходные записи, source namespace, корректную календарную точность и 4 уже связанных с каноном царствования без дублей в общей годовой VIEW.

Команды `python3 -m scripts.atlas_v2_roles --year 1685 --context ctx-tsardom` и `--year 1795 --context ctx-world-frrep` показывают read-only кандидатов; пересечения по году не доказывают одновременность правления.

**Следующий контракт P3:** династические дома, родство, личные унии и международные отношения, также без автоматического вывода о фактическом контроле территорий. Production v1 и GitHub Pages не мигрированы.
